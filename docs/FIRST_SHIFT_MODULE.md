# Модуль «Первая смена»

## Запуск для проверки

```bash
cd frontend
npm ci
npm run dev
```

Открыть `/academy-module.html`. Главная `/` остаётся прежней. `npm run build` создаёт обе HTML страницы в `dist`; `npm run preview` позволяет проверить production сборку. Для автоматической проверки логики: `npm run test:academy` (Node 24+, без дополнительных зависимостей). Для визуальной QA на 320 и 390 px: `/tests/responsive.html` в dev-режиме; тестовая страница не входит в production build.

## Состав

- `content.ts`: пять ситуаций, по три узла в каждой, 35 вариантов действий. Каждое первое решение ведёт к продолжению или исправлению, затем — к следующей ситуации. Последствия — учебные гипотезы, а не обещание реакции гостя.
- `progress.ts`: чистая машина переходов и строгая проверка версии/маршрута сохранения. Сохраняются решения по стабильным ID и факт прочтения разбора. Нельзя засчитать ситуацию, не открыв продолжение после разбора. Повторный клик не создаёт два решения.
- `AcademyModule.tsx`: маршрут, ситуации, разбор, итоговый журнал решений, вопросы наставнику и подтверждаемый сброс.
- `module.css`: изолированные стили, touch-кнопки, focus, масштабируемый текст и мобильная компоновка.
- `academy-module.html` / `main.tsx`: отдельная точка входа для ревью, без вмешательства в приложение.

Прогресс локальный, не синхронизируется между устройствами, не является оценкой сотрудника. В самостоятельном режиме один профиль на браузер; очистка данных браузера удаляет результат. Не использовать его для учёта допуска/аттестации. При недоступном storage модуль работает в памяти с видимым предупреждением; повреждённое сохранение не перезаписывается до явного повтора сохранения. Одновременное прохождение в нескольких вкладках не поддерживается: последняя запись побеждает.

## Перенос в актуальную академию

1. Сначала установить действительный источник (см. `ACADEMY_SOURCE_AUDIT.md`).
2. Перенести папку academy и импортировать её CSS в route bundle. Не заменять существующий App или auth flow.
3. Смонтировать внутри авторизованной зоны: `<AcademyModule key={employee.id} learnerId={employee.id} />`, где ID — стабильный неприватный идентификатор. React key обязателен при смене аккаунта, чтобы состояние предыдущего сотрудника размонтировалось. Не передавать телефон, токен или пароль как ID.
4. Доступ к экрану обеспечивает существующая авторизация. Сам модуль не реализует контроль доступа. Текущие hash-переходы зарезервированы для самостоятельного entry; при hash-router хоста заменить адаптер маршрутизации, прежде чем интегрировать.
5. Для серверного учёта заменить localStorage адаптером API после проверки реальной модели пользователей, версионирования контента и доступа. До этого не показывать наставнику выдуманную серверную статистику.
6. Согласовать материал ниже, проверить маршрут назад в академию и завершение с настоящей auth-сессией, затем отдельным решением публиковать.

## Что согласовать с руководителем до обучения сотрудников

Все ситуации помечены как пилот, не официальный регламент. Нужны подтверждения:

- кто наставник, как распределяются столы и кто отвечает за размещение/брони;
- где актуальные сведения меню и кому передавать запросы по аллергенам/риску контакта;
- кто сообщает статус кухни, как согласуют замену, отмену, исправление и компенсацию;
- как приглашать ответственного сотрудника при конфликте;
- какие из авторских учебных примеров соответствуют реальной работе паба.

Нет придуманных временных нормативов, обязательных приветствий, размеров скидок и обещаний гостям. Язык — естественное общение, честные уточнения и уважение к профессии. Итоги не выдают сертификат или допуск.
